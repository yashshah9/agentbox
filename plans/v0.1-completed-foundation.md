## 1. Executive summary

v0.1 establishes the **minimum viable product** for agentbox: a self-hosted HTTP service that executes untrusted Python code and returns structured stdout/stderr/exit metadata. The release ships a FastAPI API, a subprocess-based sandbox backend (explicitly **not production-safe**), a Python SDK, Docker Compose deployment with health checks, and three automated tests.

This milestone validates the core developer experience (`docker compose up` → `POST /v1/run` → result) before investing in gVisor isolation, warm pools, and multi-runtime support in v0.2+.

---

## 2. Goals

### 2.1 Primary goals

- Provide a working HTTP API for remote code execution suitable for local development and integration prototyping.
- Ship a Python SDK that wraps the API with a minimal, typed client surface.
- Enable single-node deployment via Docker Compose with an orchestrator-friendly health endpoint.
- Establish project scaffolding: packaging, config, CLI, tests, and documentation conventions.

### 2.2 Non-goals (deferred to v0.2+)

- Production-grade process/network isolation (gVisor, cgroups, seccomp).
- Warm sandbox pools or snapshot/restore.
- Non-Python runtimes (Node.js, shell).
- Default-deny egress or network policy enforcement.
- TypeScript SDK.
- Per-request CPU/memory resource limits API.
- Multi-tenant auth, rate limiting, or audit logging.

## 4. Deliverables

### 4.1 FastAPI service — `GET /health`

**Purpose:** Liveness/readiness probe for Docker, Kubernetes, and load balancers.

**Implementation:**

- Route: `GET /health`
- Response (200): JSON body with `status`, `version`, and `backend` fields.
- No authentication required in v0.1.
- Synchronous handler; no dependency on sandbox availability.

**Example response:**

```json
{
  "status": "ok",
  "version": "0.1.0",
  "backend": "subprocess"
}
```

---

### 4.2 FastAPI service — `POST /v1/run`

**Purpose:** Execute user-supplied Python code and return captured output.

**Request schema (`RunRequest`):**

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `code` | string | yes | 1–100,000 characters |
| `language` | string | no | default `"python"`; only `"python"` supported |

**Response schema (`RunResponse`):**

| Field | Type | Description |
|-------|------|-------------|
| `stdout` | string | Captured standard output (truncated) |
| `stderr` | string | Captured standard error (truncated) |
| `exit_code` | int | Process exit code |
| `duration_ms` | int | Wall-clock execution time in milliseconds |

**Error handling:**

| Condition | HTTP status | Detail |
|-----------|-------------|--------|
| Unsupported `language` | 400 | `"Unsupported language: {language}"` |
| Execution timeout | 408 | `"Execution timed out"` |
| Validation failure (empty/oversized code) | 422 | Pydantic validation error |

---

### 4.3 Subprocess sandbox backend (`SubprocessSandbox`)

**Purpose:** MVP code runner for development and API contract validation.

**Behavior:**

1. Create a temporary directory (`agentbox-*` prefix).
2. Write user code to `main.py` inside the temp directory.
3. Execute `python3 main.py` via `subprocess.run` with `cwd` set to the temp directory.
4. Capture stdout/stderr as text; enforce configurable timeout.
5. Truncate stdout/stderr to `max_output_bytes` (default 1 MiB).
6. Return `RunResult` dataclass with stdout, stderr, exit_code, duration_ms.
7. Temp directory is destroyed on context exit.

**Configuration (via `Settings`):**

| Variable | Default | Description |
|----------|---------|-------------|
| `AGENTBOX_DEFAULT_TIMEOUT_SECONDS` | `30` | Subprocess timeout |
| `AGENTBOX_MAX_OUTPUT_BYTES` | `1048576` | Max stdout/stderr capture per stream |
| `AGENTBOX_SANDBOX_BACKEND` | `subprocess` | Backend selector (future backends stubbed in config) |

**Security posture (explicit):**

> **NOT production-safe.** The subprocess backend runs code in the same OS namespace as the API server. It provides temp-directory isolation and timeout/output caps only. It does **not** provide kernel-level sandboxing, network isolation, or resource cgroup limits. Documented upgrade path: gVisor `runsc` backend in v0.2 M1.

### 4.4 Python SDK (`AgentboxClient`)

**Purpose:** Thin HTTP client for agent integrations and scripting.

**Surface area:**

| Method | HTTP mapping | Returns |
|--------|--------------|---------|
| `health()` | `GET /health` | `dict[str, str]` |
| `run(code, language="python")` | `POST /v1/run` | `dict[str, object]` |
| `close()` | — | Closes underlying httpx client |

**Defaults:**

- Base URL: `http://localhost:8080`
- HTTP timeout: 60 seconds (client-side; separate from sandbox execution timeout)

**Example usage:**

```python
from agentbox.sdk.client import AgentboxClient

client = AgentboxClient("http://localhost:8080")
print(client.health())
print(client.run("print('hello')"))
client.close()
```

## 7. Known limitations

| Limitation | Impact | Mitigation (v0.2+) |
|------------|--------|---------------------|
| Subprocess sandbox | Code runs in API process namespace; trivial escape to host | gVisor `runsc` backend (M1) |
| Python-only runtime | Node/shell agents cannot execute natively | Node.js runtime (M4) |
| Cold start per request | No pool; each run spawns fresh subprocess | Warm pool (M2) |
| No filesystem persistence | Cannot snapshot workspace state | Snapshot/restore (M3) |
| No network policy | Untrusted code can reach network | Default-deny egress (M5) |
| No resource limits API | CPU/memory not capped per run | Resource limits API (M6) |
| Single-node only | No horizontal scaling story | Out of scope until post-v0.2 |

## 8. Risks (retrospective)

| Risk | Severity | Outcome | Lesson |
|------|----------|---------|--------|
| Subprocess mistaken for secure sandbox | High | Mitigated via README warnings, `/health` backend field, inline `ponytail:` comment | Always surface backend identity in API and docs |
| Output bomb ( huge stdout ) | Medium | Mitigated via `max_output_bytes` truncation | Byte caps required from day one |
| Timeout edge cases ( hung subprocess ) | Medium | Mitigated via `subprocess.run(timeout=...)` | Map timeout to HTTP 408 consistently |
| Scope creep into gVisor for v0.1 | Medium | Avoided; subprocess MVP shipped on time | Validate API/SDK contract before isolation investment |
| Python 3.9 vs 3.11 mismatch in local venv | Low | `requires-python >= 3.11` in pyproject | Pin Python version in Dockerfile and CI |
